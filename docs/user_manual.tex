\section{Purpose and Scope}
QuantumTransportEOM is a standalone Python package for analytical and numerical workflows in quantum transport theory, with special focus on:
\begin{itemize}[leftmargin=1.5em]
  \item commutator and anticommutator calculations for fermionic, bosonic, and mixed operator algebras,
  \item equation-of-motion (EOM) closure analysis for predefined and \emph{arbitrary user-supplied} Hamiltonians (\texttt{custom\_model} / \texttt{CustomModel}), with automatic basis expansion and mean-field (Hartree) or Hubbard-I truncations,
  \item Keldysh contour algebra: Langreth rules, Dyson equations, symbolic Meir--Wingreen currents, and numeric Keldysh self-energies,
  \item Rashba-Hubbard tight-binding ring Hamiltonians in real space and reciprocal space,
  \item retarded, advanced, lesser, and greater Green functions, both symbolic and numeric,
  \item numeric two-terminal devices (\texttt{MatrixDevice} and friends) with structured leads (wide band, spin polarized, ferromagnetic, semi-infinite chain, sampled),
  \item interacting open Anderson dots (Hubbard-I / Hartree self-energies, self-consistent occupations, finite-bias currents),
  \item transport observables: transmission, conductance, Landauer and Meir--Wingreen currents, spin-resolved variants, persistent currents, and a Drude finite-difference proxy,
  \item \emph{acceleration}: batched frequency sweeps (stacked LAPACK/BLAS), multi-core CPU execution via \texttt{workers=}, and optional CUDA GPU execution via CuPy (\texttt{backend="cupy"}).
\end{itemize}

This manual describes the full package architecture, installation, API behavior, formula conventions, and practical workflows.

\section{Mathematical Conventions}
\subsection{Basis and Indexing}
In the numerical modules, the spinful site basis is ordered as
\[
(0,\uparrow),(0,\downarrow),(1,\uparrow),(1,\downarrow),\dots,(N-1,\uparrow),(N-1,\downarrow).
\]
Hence the Hamiltonian dimension is \(2N \times 2N\).

\subsection{Rashba-Hubbard Ring Hamiltonian}
The implemented mean-field real-space Hamiltonian is:
\begin{align}
H &= \sum_{n,\sigma} E'_{n\sigma}\, c^\dagger_{n\sigma} c_{n\sigma}
 + \sum_n \left(c^\dagger_{n+1}\,\Gamma_{n+1,n}\,c_n + \mathrm{h.c.}\right),\\
E'_{n\uparrow} &= E_{n\uparrow} + U\langle n_{n\downarrow}\rangle,\quad
E'_{n\downarrow} = E_{n\downarrow} + U\langle n_{n\uparrow}\rangle.
\end{align}
The nearest-neighbor spin matrix \(\Gamma_{n+1,n}\) contains both hopping and Rashba terms with Peierls phase
\[
\theta = \frac{2\pi}{N}\frac{\phi}{\phi_0}.
\]

\subsection{Green Functions}
For a quadratic Hamiltonian \(H\):
\begin{align}
G^r(\omega) &= \left[(\omega + i\eta)I - H\right]^{-1},\\
G^a(\omega) &= \left[(\omega - i\eta)I - H\right]^{-1}.
\end{align}
Equilibrium lesser and greater functions:
\begin{align}
G^<(\omega) &= f(\omega)\left(G^a(\omega)-G^r(\omega)\right),\\
G^>(\omega) &= \left(f(\omega)-1\right)\left(G^a(\omega)-G^r(\omega)\right),
\end{align}
with Fermi function \(f(\omega)\).

\subsection{Transport Quantities}
The package computes:
\begin{itemize}[leftmargin=1.5em]
  \item \(J_c(\omega)\): current density integrand built from matrix elements of \(G^r-G^a\), hopping \(\gamma\), Rashba \(\lambda_R\), and flux phase factors.
  \item \(I_c(\phi)\): persistent current by numerical integration over \(\omega\):
  \[
  I_c(\phi)=\int J_c(\omega)\,d\omega.
  \]
  \item Drude proxy:
  \[
  D \sim \frac{dI}{d\phi}\approx\frac{I(\phi+\delta\phi)-I(\phi-\delta\phi)}{2\delta\phi}.
  \]
\end{itemize}

Important implementation details:
\begin{itemize}[leftmargin=1.5em]
  \item Zero-temperature filling with optional fractional last occupation for non-integer \(N_e\).
  \item Density matrix construction:
  \[
  \rho = V \,\mathrm{diag}(occ)\, V^\dagger.
  \]
  \item Spin densities sampled from diagonal entries in interleaved basis:
  \[
  n_{\uparrow}(n)=\rho_{2n,2n},\quad n_{\downarrow}(n)=\rho_{2n+1,2n+1}.
  \]
\end{itemize}

\section{End-to-End Workflows}
\subsection{Workflow A: HF + Current + Drude}
\begin{lstlisting}[style=py]
import numpy as np
from quantum_transport import (
    hartree_fock_self_consistent,
    persistent_current,
    drude_weight,
)

n_sites = 8
n_electrons = 8
gamma = 1.0
lambda_r = 0.4
u_hubbard = 0.4
phi = 0.2
dphi = 1e-3

hf = hartree_fock_self_consistent(
    n_sites=n_sites,
    n_electrons=n_electrons,
    gamma=gamma,
    lambda_r=lambda_r,
    phi_over_phi0=phi,
    u_hubbard=u_hubbard,
)

mu = 0.5 * (hf.eigenvalues[n_electrons - 1] + hf.eigenvalues[n_electrons])
omega_grid = np.linspace(-6.0, 6.0, 2001)

I0 = persistent_current(
    hamiltonian=hf.hamiltonian,
    omega_grid=omega_grid,
    n_sites=n_sites,
    gamma=gamma,
    lambda_r=lambda_r,
    phi_over_phi0=phi,
    mu=mu,
)

hf_plus = hartree_fock_self_consistent(n_sites, n_electrons, gamma, lambda_r, phi + dphi, u_hubbard)
hf_minus = hartree_fock_self_consistent(n_sites, n_electrons, gamma, lambda_r, phi - dphi, u_hubbard)

Iplus = persistent_current(hf_plus.hamiltonian, omega_grid, n_sites, gamma, lambda_r, phi + dphi, mu)
Iminus = persistent_current(hf_minus.hamiltonian, omega_grid, n_sites, gamma, lambda_r, phi - dphi, mu)

D = drude_weight(Iplus, Iminus, dphi)
print(I0, D)
\end{lstlisting}

\section{Custom Models and the Exact CAR Engine}
\subsection{Building a Model from Any Hamiltonian}
\texttt{CustomModel} (or the lower-level \texttt{custom\_model}) accepts an arbitrary
second-quantized Hamiltonian built from the constructors \texttt{f}/\texttt{fd}
(fermions) and \texttt{b}/\texttt{bd} (bosons). Statistics
(\texttt{"fermion"}, \texttt{"boson"}, \texttt{"mixed"}), the mode content, and a seed
operator basis (one annihilator per mode) are detected automatically:
\begin{lstlisting}[style=py]
import sympy as sp
from quantum_transport import CustomModel, n

eps, U = sp.symbols("epsilon U", real=True)
dot = CustomModel(eps*(n("up") + n("down")) + U*n("up")*n("down"))
dot.model.eom()                     # exact projected EOM
dot.model.eom(auto_expand_steps=1)  # closes on the atomic hierarchy (4x4)
dot.model.eom(truncation="hartree") # mean-field closure on the seed basis
\end{lstlisting}
Unless \texttt{check\_hermitian=False} is passed, a visibly non-Hermitian
Hamiltonian (typically a missing conjugate hopping term) raises a
\texttt{UserWarning}.

\subsection{Exact CAR Normal Ordering}
For symbolic mode labels (\texttt{"up"}, \texttt{"L"}, \dots) SymPy's
\texttt{wicks} machinery is unreliable, so custom fermionic models are processed by
an exact canonical anticommutation engine (\texttt{normal\_order\_fermionic}):
adjacent pairs are rewritten with
\begin{equation}
  c_i c_j^\dagger = \delta_{ij} - c_j^\dagger c_i ,
\end{equation}
identical adjacent operators vanish by nilpotency, and same-type runs are sorted
canonically with anticommutation signs so equivalent strings cancel. Because
\texttt{custom\_model} enumerates every ladder index as an independent orthogonal
mode, Kronecker deltas between \emph{distinct} labels are then collapsed to zero
(\texttt{collapse\_orthogonal\_mode\_deltas}). The projected EOM matrix accepts only
scalar coefficients; operator strings that do not close on the basis land in the
residuals, from which \texttt{auto\_expand\_steps} harvests new composite basis
operators.

\subsection{Generic Hartree Truncation}
\texttt{truncation="hartree"} applies a Wick-style mean-field factorization to the
cubic strings generated by quartic interactions,
\begin{equation}
  ABC \;\longrightarrow\; \langle AB\rangle C - \langle AC\rangle B + \langle BC\rangle A ,
\end{equation}
keeping density contractions $\langle c_i^\dagger c_i\rangle$ (symbols
\texttt{n\_<i>\_avg} unless numbers are supplied via
\texttt{truncation\_params=\{"occupations": ...\}}). With
\texttt{include\_fock=True} the off-diagonal coherences
$\langle c_i^\dagger c_j\rangle$ are retained as symbols. This works for any
fermionic model, not just the Anderson impurity.

\subsection{Opening a Quadratic Model into a Device}
For non-interacting fermionic Hamiltonians
$H=\sum_{ij}h_{ij}c_i^\dagger c_j$, the single-particle matrix $h$ is extracted
symbolically (\texttt{single\_particle\_hamiltonian\_matrix}) and converted into a
numeric \texttt{MatrixTransportView}:
\begin{lstlisting}[style=py]
view = model.open({"0": 0.4}, {"2": 0.4}, parameters={"t": 1.0})
\end{lstlisting}
Lead arguments accept a scalar (wide-band coupling on every site), a mapping from
mode labels to couplings (site-resolved contacts), a full coupling matrix, or a
\texttt{LeadSelfEnergy}. Interacting Hamiltonians raise a \texttt{ValueError} here;
use the EOM layer with a truncation instead.

\section{Acceleration: Batched Kernels, CPU Parallelism, GPU}
\subsection{Batched Frequency Sweeps}
All \texttt{*\_values} methods on \texttt{MatrixTransportView} and
\texttt{OpenAndersonTransportView} replace the per-frequency Python loop with
stacked linear algebra: the retarded Green function for the whole grid,
\begin{equation}
  G^r(\omega_k) = \left[(\omega_k + i\eta)\mathbb{1} - H - \Sigma^r(\omega_k)\right]^{-1},
  \qquad k = 1,\dots,n,
\end{equation}
is computed as a single batched inversion of an $(n,d,d)$ stack, and the Landauer
trace $T(\omega)=\mathrm{Re}\,\mathrm{tr}[\Gamma_L G^r \Gamma_R G^a]$ as chained
batched matrix products. The scalar per-frequency methods remain available and the
test suite enforces bit-level agreement between both paths.

\subsection{Memory Blocking and CPU Workers}
Grids are processed in blocks whose $(n_{\mathrm{block}},d,d)$ stacks stay under a
memory target (default 64\,MiB shared across workers), which caps peak memory for
large devices. Passing \texttt{workers=N} maps blocks onto $N$ threads; NumPy
releases the GIL inside LAPACK, and small-matrix factorizations (dimension
$\le 1024$) are pinned to a single BLAS thread via \texttt{threadpoolctl} --- on
many-core machines multithreaded OpenBLAS factorizations of small matrices are
otherwise up to $30\times$ slower than single-threaded ones. Typical measured
gains for a 120-orbital ring on 400 frequencies: $\sim$30\,s scalar loop
$\rightarrow$ 2.4\,s batched $\rightarrow$ $<$1\,s with \texttt{workers=8}.

\subsection{GPU Backend and Precision}
\texttt{backend="cupy"} (or \texttt{"gpu"}) runs the same kernels on a CUDA device
through CuPy; \texttt{backend="auto"} selects CuPy when a usable GPU is present
and falls back to NumPy otherwise. Install with
\texttt{pip install -e ".[gpu]"} on a CUDA 12 host.

Consumer (GeForce) GPUs execute float64 at $1/64$ of their float32 rate, so
complex128 inversions on such cards are no faster than a single CPU core. Pass
\texttt{precision="single"} to run the batched inversions in complex64 —
$\sim 10^{-5}$ relative accuracy and roughly a $10\times$ speedup on an RTX 3080
(600-orbital device, 400 frequencies: 8.5\,s CPU $\rightarrow$ 1.1\,s GPU).
Keep the default double precision for sharp resonances (tiny $\eta$) or on
datacenter GPUs with full float64 throughput. Whether \texttt{workers=} beats
the serial batched path is machine-dependent (it hinges on the local BLAS);
benchmark once with \texttt{examples/demo\_parallel\_gpu.py}.

The helpers \texttt{available\_backends()}, \texttt{get\_backend()}, and
\texttt{to\_numpy()} expose the backend layer directly, and
\texttt{parallel\_map} / \texttt{blocked\_over\_grid} serve custom sweeps:
\begin{lstlisting}[style=py]
from quantum_transport import available_backends, parallel_map
available_backends()      # {"numpy": True, "cupy": False}
T = view.transmission_values(grid, workers=8)          # CPU threads
T = view.transmission_values(grid, backend="cupy", precision="single")
occ = anderson_view.self_consistent_occupations(grid, workers=4)
\end{lstlisting}

\section{Practical Notes for Research Use}
\begin{itemize}[leftmargin=1.5em]
  \item The equilibrium lesser/greater relations implemented here assume closed-system equilibrium.
  \item For open systems with leads, use the device layer (\texttt{MatrixDevice}, \texttt{LeadSelfEnergy}) or \texttt{AndersonImpurity.open}, which assemble the contact self-energies and Keldysh equations for you.
  \item Frequency integrals use \texttt{numpy.trapezoid} on user-supplied grids; resolve sharp resonances (width $\sim\Gamma$) with an adequate grid, especially at low temperature.
  \item For production sweeps use \texttt{workers=} and, on CUDA hosts, \texttt{backend="cupy"}; \texttt{parallel\_map} parallelizes external parameter scans.
  \item \texttt{tests/test\_physics\_validation.py} pins the package to exact analytic results (Lorentzian transmission, spectral sum rule, fluctuation--dissipation, current conservation); run it after modifying physics code.
\end{itemize}

\section{Extension Roadmap}
Delivered in v0.2.0: lead self-energies and nonequilibrium transport (device layer,
open Anderson dots), arbitrary custom models with an exact CAR engine and generic
Hartree truncation, batched/parallel/GPU numerics, and analytic physics-validation
tests. Suggested next extensions:
\begin{enumerate}[leftmargin=1.5em]
  \item Exact diagonalization backend for small interacting clusters.
  \item Automatic symmetry checks (particle-hole, time reversal, inversion where applicable).
  \item Plotting utilities for spectra, \(I(\phi)\), and \(D(\lambda_R)\).
  \item Higher-order EOM truncations (second Born, GW-like) for custom models.
  \item Adaptive frequency grids for sharp resonances at low temperature.
\end{enumerate}
